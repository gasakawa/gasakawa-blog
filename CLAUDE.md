# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository structure

This directory is **not itself a git repo** — it holds two independent projects, each with its own git history and no shared root package.json/workspace config:

- `web/` — Next.js 16 (App Router) frontend, npm-managed (`package-lock.json`).
- `studio/` — Sanity Studio v6 CMS, yarn-managed (`yarn.lock`).

They are connected only through a shared Sanity backend (see below). There is no monorepo tooling (no Turborepo/Nx, no workspaces) — commands must be run from inside the relevant subdirectory.

**Current state**: both projects are fresh, essentially unmodified scaffolds (`create-next-app` and Sanity's default init). `studio/schemaTypes/index.ts` exports an empty `schemaTypes = []`, and `web/` has no Sanity client wired up yet — there is no established data-fetching pattern to follow. Expect to be building this from scratch rather than extending existing conventions.

## Commands

### web/ (run from `web/`)
- `npm run dev` — start Next.js dev server (http://localhost:3000)
- `npm run build` — production build
- `npm run start` — run the production build
- `npm run lint` — ESLint (flat config, `eslint-config-next` core-web-vitals + typescript)

There is no test setup in `web/` currently.

### studio/ (run from `studio/`)
- `yarn dev` — start Sanity Studio locally
- `yarn build` — build the studio
- `yarn start` — run the built studio
- `yarn deploy` — deploy the studio to Sanity's hosting
- `yarn deploy-graphql` — deploy the GraphQL API

## Architecture

- Both projects point at the same Sanity backend: `projectId: 'jygusuea'`, `dataset: 'production'` (set in `studio/sanity.cli.ts` and `studio/sanity.config.ts`). When wiring up `web/` to fetch content, use these same values.
- `studio/sanity.config.ts` registers `structureTool` and `visionTool`, with schema types imported from `studio/schemaTypes/index.ts`. New content types go there and must be added to the `schemaTypes` array to be registered.
- `web/` uses the App Router under `web/src/app/`, with the `@/*` path alias mapped to `web/src/*`.
